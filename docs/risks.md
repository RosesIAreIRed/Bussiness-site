# Risks (ризики)

Формат: R# — ризик → помʼякшення.

- **R1. Відсутність повного ТЗ.** Ризик прогалин обсягу та невірних пріоритетів →
  бриф зафіксовано в `docs/brief-ormilo-growth-os-ua.md`; assumptions ведуться
  явно; план перебудовується після додавання ТЗ.
- **R2. Зміни Shopify API.** Мутації/поля/webhook topics змінюються між версіями →
  версія API лише в env (`SHOPIFY_API_VERSION`), GraphQL-операції у versioned
  `.graphql` файлах, перевірка `userErrors` у кожній mutation, звірка з офіційною
  документацією перед імплементацією (правило: не вгадувати).
- **R3. Асинхронна обробка media у Shopify.** Зображення/відео обробляються
  асинхронно → статуси media проходять через polling/webhook-обробку, публікація
  не вважається завершеною до готовності media (M4).
- **R4. Отруєння черг / нескінченні ретраї.** Некоректний payload може крутитися
  вічно → Zod-валідація payload на вході процесора, обмежені attempts із backoff,
  dead-letter поведінка і алерти (базова структура вже в M0: невідомий job → failed).
- **R5. Витік секретів/PII у логи.** → центральний logger із redact-списком
  (`SENSITIVE_LOG_PATHS`), заборона логувати сирі значення env, тести на маскування.
- **R6. Юридичні/платформні ризики research-імпорту.** Скрейпінг заборонених джерел
  → імпорт лише з дозволених джерел або browser-assisted capture з ручним тригером;
  окремий adapter, відділений від власних кампаній (бриф, рішення 6).
- **R7. Meta Marketing API доступ.** Токени, review, ad account обмеження →
  Meta-milestone відкладено до стабільного Shopify flow; усе створюється Paused.
- **R8. Вартість AI-генерацій.** Неконтрольовані витрати на батчі → generation cost
  фіксується в Creative Batch (M3), ліміти на batch, mock-провайдери в dev.
- **R9. Ресурсоємність рендерингу.** Remotion/FFmpeg на слабких інстансах →
  окремий render-worker із concurrency 1, черга з backpressure; горизонтальне
  масштабування — окремими процесами.
- **R10. Дрейф мажорних версій (A2).** Відкладений апгрейд накопичує борг →
  після M1 — регулярні керовані апгрейди (Next 16 / Prisma 7 / ESLint 10 / Vitest 4 /
  TS 6→7), кожен окремим PR із зеленим CI.
- **R11. Фінансові дії без нагляду.** Автозамовлення постачальнику може створити
  реальні витрати → ManualSupplierAdapter первинно; у development реальні supplier
  orders заборонені; будь-яка автоматична оплата — лише після стабільного тестування
  і лише через Approval Queue.
- **R12. Монорепний дрейф залежностей.** Розбіжні версії між пакетами → pnpm catalog,
  єдиний lockfile, CI на кожен PR.
